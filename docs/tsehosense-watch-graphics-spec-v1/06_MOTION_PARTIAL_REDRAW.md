# 06. Движение и частичная перерисовка

## Основной принцип

Интерфейс проектируется как событийный статический экран. Движение сообщает о
переходе или ожидании, но не украшает.

## Обновление зон

| Зона | Триггер |
|---|---|
| время | граница минуты |
| батарея | событие драйвера или медленный таймер |
| погода | новые данные телефона |
| текущее устройство | смена контекста/связи |
| телефонный счётчик | изменение потока телефона |
| счётчик экосистемы | изменение журнала |
| параметры | новый confirmed snapshot |
| command progress | изменение транспортной фазы |
| hold progress | локальный input tick |

Каждая зона объявляет bounds invalidation. Renderer объединяет пересекающиеся
rect, но соблюдает `maxDirtyRects = 8`.

## Перелистывание

Во время свайпа:

1. не перерисовывать два полноценных bitmap-экрана;
2. текущий и следующий экраны представить белыми контурами ключевых областей;
3. двигать контур с шагом, подходящим дисплею;
4. после порога жеста очистить экран и один раз нарисовать финальное состояние;
5. при отмене вернуть текущий экран.

Целевая длительность визуального завершения: 120–180 ms. При медленном e-paper
профиле переход можно заменить мгновенной сменой с коротким outline feedback.

## Разрешённая анимация

- отправка/выполнение: вращение или 4 дискретные фазы;
- hold: линейное заполнение;
- toast: появление снизу и исчезновение;
- focus/press: инверсия.

Не использовать bounce, spring, scale, blur, fade всего экрана.

## Частоты

- normal budget: до 1 fps для фоновых изменений;
- интерактивный hold: backend может временно обновлять только dirty rect
  кнопки с 10–20 fps, если дисплей допускает;
- spinner: 1–2 fps достаточно для low-power;
- ambient: только минута и новые обязательные маркеры.

## Очистка dirty rect

Перед перерисовкой прямоугольника:

1. clip к дисплею и маске формы;
2. заполнить surface;
3. заново нарисовать все компоненты, пересекающие rect, в порядке слоёв;
4. отправить минимальный aligned block драйверу.

Для page/byte-oriented mono framebuffer расширять x/y до требований контроллера,
но не менять логический dirty rect.

## Приоритет прерываний

`blocking event > important event > critical request > command > ordinary toast`.

При появлении верхнего слоя нижний слой замораживает анимацию, но сохраняет
состояние. После закрытия renderer перерисовывает открывшийся слой полностью.

## Защита от мерцания

- не очищать весь framebuffer при обновлении одной цифры;
- при смене времени перерисовывать весь time bounds, а не отдельные glyph,
  чтобы избежать остатков кернинга;
- не использовать чересстрочную заливку в мелком тексте;
- при e-paper учитывать ghosting отдельным hardware profile и периодическим
  full refresh, не менять для этого семантику layout.
