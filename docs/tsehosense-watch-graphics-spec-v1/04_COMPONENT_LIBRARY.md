# 04. Библиотека компонентов

Компонент — не виджет конкретного GUI toolkit, а графический контракт. Backend
на C может реализовать его функцией, командным буфером или набором примитивов.

## Общие состояния

Каждый интерактивный компонент поддерживает:

- `idle`;
- `pressed` — краткая инверсия или контур, без анимации масштаба;
- `focused` — для crown/кнопочной навигации, рамка 1–2 px;
- `disabled` — действие отсутствует из hit map; серый сам по себе недостаточен;
- `busy` — отдельный экран/слой состояния, не spinner внутри строки;
- `confirmed` — только после ответа источника.

## `ScreenHeader`

Состав: back icon, eyebrow, title, нижний divider 2 px.

Контракт:

- back icon всегда в hit target 44 × 44;
- title однострочный;
- если title не входит, выбирать явный размер из профиля, не ужимать
  горизонтально;
- eyebrow обрезается многоточием и не переносится;
- на корневом экране back может отсутствовать, но title не сдвигается
  произвольно: используется отдельный root-header profile.

## `ValueWithUnit`

Состав: крупное значение и меньшая единица/порог.

- значение не обрезывать;
- единицу держать рядом или по правому краю строки;
- baseline должен быть оптическим, не математическим;
- `−`, десятичная точка и `°` входят в тестовый набор каждого bitmap-шрифта.

## `StatusCell`

Иконка + число. Две ячейки главного экрана равны.

- иконка 38 квадрат / 27 круг;
- gap 7 / 5;
- значение 30 / 24;
- вертикальный divider 2 px, высота 38 / 32;
- вся ячейка кликабельна.

## `ContextDevice`

Крупный id, статус второй строкой, `CaretRight`.

- квадрат: id 56, status 20, caret 60 bold;
- круг: id 42, status 17, caret 29 bold;
- короткий id является первичным именем; длинное паспортное название
  показывается внутри устройства;
- при отсутствии контекста сохраняется зона: `НЕТ УСТРОЙСТВ` или последнее
  известное устройство с явным `НЕТ СВЯЗИ`.

## `UnreadCounter`

Иконка потока + целое число. Телефон и экосистема — два разных экземпляра.

- нулевой счётчик может скрыть число, но зона сохраняет навигационную роль;
- `99+` — максимальная строка;
- не объединять потоки;
- центральное `N рядом` не является уведомлением.

## `ListRow`

Полноширинная строка 55–64 px.

- title;
- необязательные subtitle, state, timestamp;
- leading icon;
- trailing caret;
- divider 1 px;
- вся строка — единая hit area;
- длинный subtitle получает ellipsis;
- важное значение не получает ellipsis.

## `PrimaryMetricPair`

Две равные ячейки: label + value. Высота 78 / 70.

- label 10 / 8;
- value 31 / 24;
- divider 1 px;
- более важный параметр слева;
- если параметр один, он занимает всю ширину и может получить увеличенный
  размер из size class;
- если главных параметров больше двух, показывать два первых и переход к
  таблице.

## `ActionSplit`

Две равные нижние команды, высота 56 / 49.

- icon 19–21;
- label 9–11;
- divider 1 px;
- опасное действие не помещать рядом с обычным без явной иконки/формулировки;
- primary action допускает белую заливку, вторичное остаётся контурным.

## `NumericEditor`

Структура:

- значение 58 / 48;
- единица 17 / 14;
- stepper: минус / шаг / плюс, 58 / 52;
- диапазон 18 / 17;
- кнопка применения 45 / 42.

Локальное изменение является draft. На сводке значение меняется только после
подтверждения устройства.

## `EnumSelector`

Три строки по 48 / 45. Выбор выражается белой строкой и fill-иконкой
`CheckCircle`; цвет не нужен.

## `HoldConfirm`

- высота 45 / 41;
- border 2;
- удержание 1,5 с;
- слева направо заполняется белым;
- icon и label используют инверсию поверх fill;
- отпускание, уход указателя, cancel или key-up обнуляют прогресс;
- короткий тап не создаёт команду.

На framebuffer без blend сначала рисовать fill, затем glyph/text выбранным
инверсным цветом для каждого пикселя или иметь две маски.

## `Progress4`

Четыре сегмента, gap 4, height 8. Заполненный белый, будущий — inactive.
Показывает транспортную фазу, но не заменяет текст `ОТПРАВКА / ПРИНЯТА /
ВЫПОЛНЯЕТСЯ / ГОТОВО`.

## `EventToast`

Обычное событие поверх нижней части текущего экрана.

- border 2;
- icon, device id, title, caret;
- автоматически исчезает;
- тап открывает устройство/событие;
- не блокирует физическую кнопку назад;
- после исчезновения остаётся запись в журнале.

## `EventOverlayImportant`

Полный экран, border 2, кнопка `позже`, значение/порог, две команды.
Скрывает текущий экран, но не уничтожает его состояние.

## `EventOverlayBlocking`

Полный экран, border 4, без крестика и `позже`. Только явная кнопка
квитирования. Квитирование означает «оператор увидел», а не «причина устранена».

## `CommandOverlay`

Полноэкранный статус команды:

1. крупная иконка;
2. источник и тип;
3. фаза;
4. действие;
5. четыре сегмента прогресса;
6. транспортная поясняющая строка;
7. при ошибке — `НАЗАД` и `ПОВТОРИТЬ`.

В normal animation вращается только `Radio`/`CircleNotch`. В low-power режиме
вместо вращения менять четыре дискретные фазы не чаще 2 fps либо показывать
статичный glyph.

## Слойность

Рекомендуемые логические слои:

| Layer | Содержание |
|---:|---|
| 0 | текущий экран |
| 10 | transient touch/focus |
| 20 | обычная event toast |
| 25 | command status |
| 26 | critical authorization request |
| 30 | important/blocking event |

Блокирующее событие всегда выше команды и запроса разрешения.
