# Универсальный интерфейс ЦехоСенс — пакет требований v0.1

Этот пакет описывает, как превратить паспорта устройств, каналы, события и
команды ЦехоСенс в единый интерфейс для:

- часов 256×256 с круглым или квадратным экраном;
- локального дисплея на шлюзе;
- браслета или переносной панели 3–4";
- web-интерфейса;
- предпросмотра в ЦехоЛаб.

Документы предназначены прежде всего для Codex, который будет работать с
основным репозиторием системы и IDE. Это архитектурное задание, а не требование
немедленно реализовать весь слой целиком.

## Главное решение

Устройство не передаёт исполняемый код и не описывает пиксельную компоновку.
Оно предоставляет семантику:

- что измеряется;
- текущее значение и качество;
- единицу и формат;
- важность и видимость;
- нормальные и аварийные диапазоны;
- доступные команды;
- класс риска каждой команды;
- короткие и полные подписи.

Шлюз объединяет данные разных устройств в нормализованную `UI View Model`.
Renderer получает эту модель и выбирает ограниченный шаблон под конкретный
`Display Profile`. Шкурка задаёт визуальные токены, иконки и варианты
шаблонов, но не может менять смысл данных и правила безопасности.

```text
паспорт + channel schema + live values + события + capabilities
                              │
                              ▼
                    UI View Model compiler
                              │
             ┌────────────────┼────────────────┐
             ▼                ▼                ▼
       часы 256×256       дисплей шлюза       web/IDE preview
       mono renderer       local renderer      reference renderer
```

## Источники истины

При конфликте применять порядок:

1. safety policy и protected identity устройства;
2. channel schema и capability schema;
3. паспорт установки;
4. нормализованная UI View Model;
5. Display Profile;
6. skin package;
7. локальные пользовательские настройки представления.

Шкурка или локальная настройка могут скрывать второстепенный параметр,
переставлять безопасные элементы или менять размер текста. Они не могут:

- понижать класс риска команды;
- превращать `critical` в непосредственно исполнимое действие;
- скрывать активное блокирующее событие;
- подменять единицу, границы или источник значения;
- отображать неподтверждённое значение как подтверждённое.

## Область первой реализации

Первый вертикальный срез должен пройти путь:

```text
catalog/channel schema
  → паспорт PUMP-2
    → live snapshot
      → View Model
        → ЦехоЛаб preview
          → reference renderer
```

В срез входят:

- сводка PUMP-2;
- список параметров;
- guarded-команда смены режима;
- critical-запрос остановки;
- обычное и блокирующее события;
- квадратный и круглый 256×256;
- один более крупный прямоугольный профиль.

Embedded renderer на C начинается после стабилизации View Model и reference
renderer. До этого IDE должна уметь валидировать и показывать весь сценарий.
